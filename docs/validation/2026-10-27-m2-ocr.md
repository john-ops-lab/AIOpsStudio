# M2 本地 OCR 审查与补修

本记录是公开脱敏摘要，原始评论、模型会话、首败日志和运行证据保留在仓库外。审查只针对 PR #17；原 Mac 实例未更新，未合并 PR。

## 审查范围与过程

使用 `open-code-review` CLI，显式选择 `--provider chatgpt --model gpt-6-astra`。初轮审查 main 到 M2 初版提交的固定范围，35 个选中文件全部完成，0 失败，生成 15 条问题（5 high、10 medium）。工具默认排除测试和不支持的文档类型，这些文件另由实际回归和规格检查验证，不宣称 OCR 覆盖全部改动文件。

第一次仅覆盖模型名时仍走原默认 provider，所有请求失败，没有形成有效 Astra 审查；随后显式切换服务并保留失败记录，没有修改全局 provider 配置。正确服务的初轮完成后才进入修复。

## 已修复的问题

| 来源 | 问题 | 修复与验证 |
| --- | --- | --- |
| Astra | `$dynamicRef` 可触发隐式远程 Schema 检索 | 统一离线 registry，实际 Skill/MCP 输入验证也禁止 HTTP/文件检索；本地引用与锚点正例保留 |
| Astra | 把实例样本的 `$ref` 当子 Schema | 按规范的子 Schema 位置遍历，examples/default/const/enum 中的原数据保持 |
| Astra | 同步评分阻塞事件循环及全局 Store 锁 | 重评分/文件哈希移到工作线程及锁外，短事务核对评分状态；正式发布采用锁外最终文件核验、5秒单调时钟服务端票据、事务内数据库 CAS 与制品原子激活/回滚 |
| Astra | 修改 title 或未消费字段绕过首次失败约束 | 使用服务端实际执行输入规范摘要，显式 retry 不可晋升首次证明 |
| Astra | 切换当前正式版后复用旧评价 | 候选所选版本与当前正式基线身份同时绑定；回退或首次发布状态变化使旧评价失效 |
| Astra | 回放证明未绑定完整实现 | 纳入 evaluator 全部 Python 实现、实际固定输入与 oracle 字节；不改原冻结材料与应用摘要语义 |
| Astra | 入口退出后遗留同组 worker | 无论入口状态都检查并停止本次完整进程组；不能确认停止时保留锁和私有输出，拒绝并发 |
| Astra 复审 | 纯僵尸进程让回放锁永久保持 | 区分本次 PID/PGID 的可执行成员与 Z/X；兼容 Mac 对僵尸组返回 EPERM，探测失败仍保守拒绝并发 |
| Astra 补审 | 最终提交仍在共享锁内递归扫描文件 metadata | 文件集合发现和扫描移到锁外，最终事务只重核受控预检与数据库状态；慢 metadata 并发读取回归单独验证 |
| Astra 补审 | PID 在存在性预检与 ps 之间退出，误阻止锁恢复 | 对单 PID 无匹配的明确状态再次确认退出，未知探测仍保守保留锁 |
| Astra | 终态但仍交付中的 worker 可被备份 | 同锁拒绝尚未释放的 worker slot，包括过期但未显式收尾的状态 |
| Astra | 主密钥位于制品根内会进入备份 | CLI 在数据库初始化前拒绝路径，API 接收 key 路径并做同样检查；无路径时也检测同一明文 key，失败清理整个本次包 |
| Astra | 非字符串 mode 导致类型异常 | 会话和直接运行入口统一返回422，消息/运行不新增 |
| Astra | 删除 pending 被误作完成并丢弃凭据 | 显示未完成状态，保留同一 token 重试；结果明确 complete 后才关闭，阻止 Escape 丢弃窗口 |
| Astra | 分页失败清空历史且不能重试原游标 | 保留已授权页面，显式重试同游标；权限失效仍清缓存 |
| Astra | 响应丢失后新报告改变 analyze 幂等身份 | 指纹只包含实际发送字段，普通分析不包含未发送的 parent |
| Astra | 已删除附件仍隐藏在待发送集合 | 删除完成后移除 staged ID，后续消息不携带已删附件 |
| Astra | 已归档会话恢复错误不可见 | 常驻通知区展示管理错误，Composer 隐藏时仍可见 |
| 辅助交叉复现 | 恢复误改业务 JSON 中同名路径键 | 按文档类型和固定 schema 位置重定位，inputs/report/history/补读内容及未知文档原值保持 |
| 辅助交叉复现 | 用户文本中的明文主密钥可进入 database.json | 序列化数据库写入前同样检查本次主密钥，命中时拒绝并清理整个本次包 |

## 本轮验证

- 最终源码后端完整回归：654 passed、1 skipped（补修过程中另保留629和642项通过的完整回归记录）。显式隔离 PostgreSQL 恢复检查单独 1 passed；仅使用限额临时数据库容器，随后确认移除。
- Schema 首败 8 failed/1 passed，包含通过内存 hook 捕获旧验证器检索动作（没有实际联网）；修后相关集合155项通过。
- 恢复业务路径首败1项失败，补修后新正例及原恢复/档案检查通过；备份租约/密钥首败5项失败，数据库正文含密钥补修首败1 failed/1 passed；补修后相关集合45项通过，数据库明文命中在写入前拒绝且原记录不变。
- 管理质量首败8项失败；补修验证慢评分/慢发布期间同 Store 健康读取可响应，预检后基线/文件/记录变化拒绝，以及制品写入失败回滚。最终 metadata 慢扫描回归首败2项失败；补修后相关集合87项通过，额外核对慢扫描不消耗票据有效期、等待锁过期拒绝，以及回滚清理期间同 Store 健康读取可响应。
- 回放指纹与进程组清理首败8项失败；复审僵尸探测首败另行保留。PID退出竞态补充回归首败4项失败；补修后专门回归26项及既有流水线回归8项通过，包含入口早退、后代忽略 TERM、真实僵尸组、混合活动成员、完整组回收和未停组保留锁。
- 前端 TypeScript/Vite 构建通过。Chrome 使用独立合成 HTTP 故障 fixture，五项实际交互均通过：分页失败保留与重试、pending同token重试、删除暂存附件后发送空附件集合、受理响应丢失后重试仅一个消息ID/轮次、归档恢复错误可见。该 fixture 不调用真实模型或来源，不替代真实数据库验收。
- 最终源码固定回放门禁实际执行通过：18例、105断言中102通过、0失败、3范围外unknown；完整分母保持，未计未知为通过。

本轮不重复没有受影响的 MiniMax 样本，也不把初版模型结果改称本轮重新运行。初版真实 MiniMax、浏览器与原端到端结果仍见 [M2 集成验收](2026-10-27-m2.md)。

## 复审与交付

补修范围共14个产品文件。第一次复审完成12个，两个同组文件遇到服务端504未完成，并另指出纯僵尸回收问题；未把部分覆盖称为通过。补审完成这两个文件后，再修复最终锁内扫描与PID退出竞态。最后三批分别复审流水线1个、备份1个、发布2个文件，均完整完成、0失败、0新问题；其余10个文件在最后修改后已有有效复审。所有有效复审均使用 `gpt-6-astra`，没有以跳过或豁免代替完成。

四份原 OpenSpec 保持独立，相关设计、任务和主规格同步补修边界。OpenSpec 全部36项严格校验通过。测试服务、临时数据库容器、浏览器标签及本次临时SQLite/制品目录已按任务身份清理；原数据库1067行、6份私有文件、70份制品及原容器/进程基线逐项复核一致。提交和推送执行正常敏感信息门禁，原始 OCR 输出、临时配置与本机路径不入 Git；远端公开安全 CI 以 PR 最新提交对应检查为准。
