# PR #15 审查、无损升级与 MiniMax 验证

本轮按用户授权先审查修复，再合并并更新 Mac，模型优先 MiniMax。代码验证、升级数据保持、真实模型往返和真实业务验收分别记录。

## 审查发现与修复

1. **旧历史读取受阻**：M1 默认拒绝缺少来源授权记录的旧报告，会隐藏已有会话及生成附件。新增离线、一次性、摘要绑定的 `legacy_archive` 清单；合法 owner 可只读查看原记录与下载原附件，显示 `legacy_unverified`。旧档案禁止继续执行、补读、历史继承和自动送模型；原内容不改，清单不自动扩容。
2. **部分覆盖被升级为完整**：Prometheus success 分支曾覆盖源显式 partial/分页未完。修复后成功响应只提供缺省值，保留源限制、续页和截断；畸形行保守处理。
3. **撤权页面残留**：轮询收到拒绝后曾保留旧报告和片段。授权失败清空缓存和已开片段，临时网络错误保留内容并提示；片段使用元数据轮询检查权限，避免重复计费补读。
4. **返回后撤权保存顺序**：源响应返回时再次检查最新权限后才保存正文，撤权拒绝不产生新证据；调用前后的权限检查分别保留。

新增 OpenSpec：`preserve-legacy-history-on-upgrade`。R02/R07 对应 delta、主规格及定向回归同步更新。原评估摘要保留原代码摘要和首败，本轮复验另记，不能把历史通过自动移到新代码。

## 升级边界

- 升级前对数据库、配置/独立密钥、制品及进程身份建立仓库外一致快照备份；原行和原文件逐项比较，新增档案清单单独核对。
- 仅替换 Mac API/Web，数据库、持久卷和已有转发保持；准备独立旧源码和旧前端构建作为回退。
- 旧业务配置原样保留，不自动推断 M1 身份/查询绑定或扩大数据权限。新业务分析仍须显式配置这些契约。真实 MiniMax 完整分析在独立 Mac 实例使用固定测试材料和真实本机 MCP HTTP 服务验证，不覆写原业务 settings。
- 原始备份、凭据、地址、运行标识、日志和现场截图不进入公开仓库。
