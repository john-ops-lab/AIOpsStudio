# PR #15 审查、无损升级与 MiniMax 验证

本轮按用户授权先审查修复，再合并并更新 Mac，模型优先 MiniMax。代码验证、升级数据保持、真实模型往返和真实业务验收分别记录。

## 审查发现与修复

1. **旧历史读取受阻**：M1 默认拒绝缺少来源授权记录的旧报告，会隐藏已有会话及生成附件。新增离线、一次性、摘要绑定的 `legacy_archive` 清单；合法 owner 可只读查看原记录与下载原附件，显示 `legacy_unverified`。旧档案禁止继续执行、补读、历史继承和自动送模型；原内容不改，清单不自动扩容。
2. **部分覆盖被升级为完整**：Prometheus success 分支曾覆盖源显式 partial/分页未完。修复后成功响应只提供缺省值，保留源限制、续页和截断；畸形行保守处理。
3. **撤权页面残留**：轮询收到拒绝后曾保留旧报告和片段。授权失败清空缓存和已开片段，临时网络错误保留内容并提示；片段使用元数据轮询检查权限，避免重复计费补读。
4. **返回后撤权保存顺序**：源响应返回时再次检查最新权限后才保存正文，撤权拒绝不产生新证据；调用前后的权限检查分别保留。

新增 OpenSpec：`preserve-legacy-history-on-upgrade`。R02/R07 对应 delta、主规格及定向回归同步更新。原评估摘要保留原代码摘要和首败，本轮复验另记，不能把历史通过自动移到新代码。

## 升级边界

- 升级前对数据库、配置/独立密钥、制品及进程身份建立仓库外一致快照备份；原行和原文件逐项比较，新增档案清单单独核对。
- 仅替换 Mac API/Web，数据库、持久卷和已有转发保持；准备独立旧源码和旧前端构建作为回退。
- 旧业务配置原样保留，不自动推断 M1 身份/查询绑定或扩大数据权限。新业务分析仍须显式配置这些契约。真实 MiniMax 完整分析在独立 Mac 实例使用固定测试材料和真实本机 MCP HTTP 服务验证，不覆写原业务 settings。
- 原始备份、凭据、地址、运行标识、日志和现场截图不进入公开仓库。

### 真实 MiniMax 端到端

首轮完整链路**失败**，原记录保留：真实MiniMax请求5次，前4次完成，重复调用同一只读MCP工具4次，证据均正确保存；第5次禁工具报告在约55秒被本地硬超时中断，当时整个attempt还剩约289秒。最终为partial、platform_template、model_generated=false，零verified claim与有效模型引用。前四次回包累计8662输入/561输出tokens，末次远端用量未知；原usage字段仍标known的问题已进入补修，不能把局部计数当完整用量。

独立oracle没有放宽：首轮虽通过真实源HTTP、证据保存、凭据不入正文、初次输入无答案、PostgreSQL持久化、附件实际下载校验、片段精确重开及Chrome失败状态展示，但这些不能替代模型最终报告。Chrome控制台无warn/error；实际报告清楚显示平台模板与partial。

代码定位发现每轮重建只发送system/user账本，丢了本attempt的assistant/tool往返协议；同时报告超时早于整体预算且取消没有更新用量未知。按[MiniMax官方OpenAI兼容协议](https://platform.minimax.io/docs/api-reference/text-openai-api)的完整助手消息连续性要求补修，OpenSpec为 `preserve-model-tool-turns`。二次测试保留原源材料、答案、Skill、模型与预算；仅在独立测试策略的新版本显式登记reasoning协议字段，原策略不改、业务配置不放宽。

补修首轮全量回归为478通过、18项subtest通过；OpenSpec首次严格校验因新增主规格Purpose过短失败，补全文档后28项通过。固定18例回放暴露真实产品退化（86通过、15失败、4未知）：新增协议首次带入未类型投影的原生工具正文，实际HTTP出站检查正确拒绝。修复按来源字段规则投影工具正文，原始证据保存与验收材料不改；该首败保留，后续复验另记。
