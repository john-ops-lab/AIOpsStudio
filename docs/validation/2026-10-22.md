## 首次失败与限制

首次真实模型尝试遇到模型超时及报告回合未完成，结果为平台模板，`model_generated=false`。早期 oracle 曾将非空 analysis 和模型被调用误判为真实模型报告；已纠正为 `passed=false`，原失败保留。后来两轮真实报告没有覆盖首次失败。

两个成功生成的报告均为部分覆盖。会话和附件链路通过不代表全部业务影响或根因已验收；用户接受仍待实际反馈。二进制文件可保存和下载，未实现内容提取；UTF-8 文本是有界用户材料，不能作为源证据。

## 公开资料边界

本页是历史结果的去标识化投影，不是原始在线验收证据，也不是当前提交或任意部署环境的验收。公开图片完全新制，只用于说明布局和职责，不作为该历史检查的截图证据。凭据检查与环境去标识化属于不同检查，原有“已知密钥未命中”不能证明所有现场信息已清除。

当前公开副本、历史和远端对象的清理状态由 [sanitize-public-history](../../openspec/changes/sanitize-public-history/proposal.md) 另行记录，不从本页历史结论推断。

## 复现入口

在已安装依赖的仓库根目录执行：

```sh
cd backend
uv run pytest -q
cd ..
node tests/server-safety.mjs
cd web
npm run build
cd ..
openspec validate --all --strict
```

正式 HTTP 检查需自行准备并启动独立 PostgreSQL 工作台，在 `backend/` 执行 `uv run python ../tests/chat_acceptance.py`。默认不调用模型；`--live` 需要显式目标及真实源配置。新执行结果应单独记录，不能回填到上述历史计数。
