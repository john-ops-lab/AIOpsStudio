## 1. 用户入口与完成标准

| 页面 | 在线查看 | 在线调用 | 在线配置 |
| --- | --- | --- | --- |
| Skill 管理 | 名称、用途、正文、参考文件、版本差异、依赖工具、可用状态、最近运行 | 选择版本和输入发起调查；草稿可显式试运行 | 新建/导入、编辑、校验、发布、启用/停用、回退默认版本 |
| MCP 管理 | 服务、连接状态、上次检查时间、工具清单、输入/输出 schema、已开放工具及引用它的 Skill | 连接测试、发现工具、参数表单或 JSON 试调、结果与错误详情 | 地址、认证引用、超时、工具白名单、启用/停用、配置版本 |
| 模型与运行配置 | 当前模型、已验证能力、任务默认值、实际生效版本 | 小型中文工具调用样本测试，展示耗时和实际用量 | Provider、模型 ID、服务地址、凭据引用、模型支持的参数、预算 |
| 调用记录与运行概览 | 调查/试调来源、执行状态、失败阶段、耗时、用量、证据及配置变更 | 打开对应调查/证据；显式发起新重试或取消运行 | 设置保留期与平台允许范围内的默认预算 |

“调用 Skill”意味着按该版本方法运行 Agent，可能多次调用工具；“调用 MCP”意味着直接执行某个具体工具，默认不调用模型。两种结果分别显示，工具成功不能显示成整个调查完成。

MCP 的在线配置范围是 AIOpsStudio 如何连接和使用已有服务。远端 MCP 的安装、进程重启、镜像升级和服务端自身设置仍由部署操作管理；页面展示已知版本和来源，不能把修改连接配置显示为远端升级完成。

首版提供服务端 Streamable HTTP 连接。需要 stdio、本地可执行命令、OAuth 动态授权、MCP Apps 或资源/提示模板交互的服务，显示对应能力尚未接入；这些能力不能因为协议存在就自动视为本项目已支持。现有 VeOps、Grafana 和应用内工单 MCP 按各自已验证配置接入，Ongrid API 在数据源设置中管理，不伪装成 MCP 服务。

## 2. Skill 内容、依赖与执行

### 2.1 内容与在线编辑

Skill 保存标准 `SKILL.md`，包含名称、说明及正文，支持 `references/` 文本参考文件。平台另保存版本 ID、内容摘要、创建人、更新时间和来源；运行输入 schema、必需/可选工具绑定及预算属于 AIOpsStudio 配置，不把自有字段宣称为 Agent Skills 标准。

编辑器提供文件树、Markdown 原文/预览、版本差异、保存状态和校验结果。中文显示名称与稳定 Skill ID 分开，已有版本不能覆盖。可新建、复制已有版本或导入内容包；导入只保存草稿，不发布、启用或执行。

首版只执行方法文本和平台已注册工具。包内脚本、可导入代码和额外程序依赖可以被识别并提示，但不会自动安装或执行；若方法必须依赖这些能力，校验结果标为不兼容，不能以“导入成功”冒充可运行。相对引用必须在包内可解析，绝对路径、越界路径、符号链接及超出文件数/大小限额的包拒绝导入；Markdown 预览不执行嵌入脚本。

校验包括 frontmatter、引用文件、输入 schema、依赖绑定、可用工具和平台兼容性。`allowed-tools` 或正文中的“必须调用”只作为声明，不能授予权限。工具可用范围由后端根据所选 Skill 及通用辅助 Skill 的显式绑定、连接配置、源端身份和当前停用状态计算；模型不能自行增加工具。

### 2.2 输入与依赖

发布配置给每个 Skill 提供输入表单：调查目的、目标/事件/工单引用、环境及适用的时间窗。不同 Skill 的必填项不同，例如当前 CMDB 查询不强制要求告警 ID；需要历史取证的影响分析必须确认固定窗口。表单与中文对话最终提交同一输入契约。

依赖按 `(server_id, original_tool_name)` 绑定，进程内 API 工具则使用稳定 provider/tool ID。必需工具不可用时阻止启动并显示具体缺项；可选工单工具缺失允许继续适用调查，但报告明确工单维度未查。影响分析与 RCA 不能仅因 GLPI 尚未部署就全局不可用。

工具绑定以不可变运行配置引用 Skill 内容版本和确切工具定义快照。发布时检查引用完整性；启动时再检查当前连接、身份和兼容性。保存配置、协议连通、工具可调用、业务查询正确分别记录，不合成一个含义不明的绿色状态。

### 2.3 试运行与指定版本

正式发起使用已发布内容和有效运行配置。草稿试运行先将当前草稿冻结成不可变测试快照，经静态校验后以 `purpose=skill_test` 创建独立 run/attempt；使用真实只读数据时页面明确显示，仍计入队列、模型/工具预算和证据留存。编辑草稿不改变已经提交的试运行，也不自动切换正式默认版本。

用户选择某个 Skill 时，后端必须确保指定正文实际进入该 attempt，不能只把名称加入候选列表后任由模型跳过。首选核验锁定版 Deep Agents 的显式 Skill 固定加载能力；若所用版本不支持，则由适配层确定性装载所选正文及受限引用。加载失败时返回明确错误，不能静默改用通用 Agent。

早期预研只验证了所选 Deep Agents 版本的部分协议样本；官方文档的固定加载和重载说明仍需按实际锁定版本验证。每个新 attempt 使用独立检查点命名空间及固定内容路径；恢复沿用旧快照，不能因 SDK 缓存或共享目录改变而读到新版。前端可继续使用同一会话，后端 attempt 的隔离规则不变。

## 3. MCP 连接、工具发现与试调

### 3.1 连接配置

每个服务有独立 `server_id`，记录显示名称、用途/环境、传输类型、服务地址、认证方式与 `secret_ref`、TLS 信任配置、连接/调用超时、返回大小上限及工具白名单。对内使用稳定 ID，不把远端 `serverInfo.name` 当全局唯一标识。

配置填写与修改先保存草稿。测试连接由 Python 后端使用该草稿的不可变测试快照执行，展示传输连通、认证、协议兼容、工具发现各阶段结果及检查时间。首版支持无认证或服务端保存的 Bearer/指定认证头；沿用现有 MCP 的证书验证，不以关闭 TLS 校验排除错误。

服务地址是有权限的用户配置，模型不能提供。服务端按环境登记目标地址、端口和证书要求，允许项目已核实的内网服务；跨目标重定向不携带认证头。连接测试不会自动调用业务工具。

### 3.2 工具目录及变更

用所协商协议的 `tools/list` 发现工具，按实际游标收齐；未查全时目录显示不完整，不能把“未返回”视为工具已删除或据此发布完整目录。保存工具原名、描述、inputSchema、可取得的 outputSchema/annotations、源端版本、协议版本、发现时间及定义摘要。

前端以服务分组展示。模型侧使用稳定且无冲突的工具别名，别名到 `(server_id, original_tool_name)` 的映射随配置保存；调用远端仍发送原名。模型供应商的名称长度/字符限制在注册时校验，不通过截断悄悄制造重名。

白名单默认关闭新增工具，只有明确检查并登记的只读工具可供 Agent 或人工试调使用。`readOnlyHint` 是描述性提示，不能代替工具行为检查、源端权限和服务端拦截。已有未知行为工具可展示其信息，执行入口显示未开放原因。

手动刷新、重新连接以及 SDK 支持的工具列表变化通知会产生候选目录和差异；不能直接扩大正式白名单。发布需检查依赖该工具的 Skill。新工具不会进入旧 attempt；旧工具删除、入参不兼容或返回 schema 变化会使相关绑定失效，受影响调用停止并给出具体原因，其他独立工具仍可使用。

目录检查在任务启动、重连及支持的变更通知后执行。远端服务无法由 AIOpsStudio 强制保持旧实现，发布本地配置不保证远端代码不变；实际调用记录远端可取得的版本和定义摘要，发现变化或结构校验失败时按上面的失效规则处理，不宣称可完全重现未知的远端实现。

### 3.3 工具试调

工具详情提供 schema 生成的表单与 JSON 编辑器，二者编辑同一参数对象；复杂 schema 无法表单化时保留 JSON 入口及后端校验。工具需要对象、数据源或时间窗时明确填写，不默认猜测标签或补漂移的相对时间。

点击调用后先创建持久 `tool_test` 任务，返回接收回执；再进入与调查相同的调度和工具包装器。首版调查、Skill 试运行、手工工具试调及模型样本测试共享一个执行槽及最多 10 项等待队列，配置编辑和本地校验无需占槽；连接探测/工具发现使用独立的有界控制请求，每服务最多一个在途请求，不启动 Agent。

每次手工调用默认一个工具请求、30 秒等待和 1 MiB 保存上限，发布配置可在平台上限内调整。客户端重复提交按 `client_request_id` 幂等返回原记录；MCP 只读工具的业务错误不自动隐藏重试。显式重试创建关联的新记录，保留第一次失败；连接/发现等协议请求单独统计，不伪装成一次业务工具调用。

结果页展示实际参数、原生 `content/structuredContent/isError`、协议错误、耗时、字节数、截断/完整性、来源和时间。HTTP 成功、MCP 工具成功和数据足以回答业务问题是三个不同判断。预览折叠/截短与实际保存截断分别标识；超过保存上限的响应只留有界诊断和明确缺口，不把不完整片段包装成完整证据。正文、图片或链接按已支持内容类型显示，不自动下载外部资源。

试调不调用模型；用户请求“用 Agent 分析这个结果”时创建新的调查 attempt，按身份、窗口、可访问范围和完整性显式引用原证据并记录模型用量。手工试调结果不会自动混入正在运行的报告。

## 4. 草稿、发布、生效与停用

### 4.1 版本实体

| 实体 | 保存内容 | 生命周期 |
| --- | --- | --- |
| SkillDraft / SkillVersion | 草稿修订号；发布或试运行时冻结的正文、参考文件、来源及摘要 | 草稿可改，版本不可改；历史引用未释放前不能删除 |
| MCPConfigVersion / ToolCatalogSnapshot | 连接参数、凭据版本引用、白名单及完整工具定义 | 测试、校验、发布；目录变化生成新快照 |
| ModelConfigVersion | Provider、模型 ID、服务地址、凭据引用、支持的参数及能力检查记录 | 草稿、测试、发布；不隐式切换模型 |
| RuntimeConfigRevision | Skill 内容及绑定、MCP/工具快照、模型、输入/输出契约、查询目录与预算的完整引用 | 校验后原子启用，新任务取得该修订号 |
| Invocation / ConfigAudit | 调查或试调来源、执行结果；配置作者、操作、版本差异及时间 | 追加记录，不覆盖首败或历史内容 |

平台自己的版本号与源系统/模型的自报版本分开；内容摘要只用于一致性验证，不证明效果正确。

### 4.2 生效规则

1. 草稿保存使用修订号做并发控制；两个页面同时编辑，过期页面收到冲突和差异，不覆盖新保存内容。
2. 发布前固定草稿修订号并验证引用、兼容性和必需配置；内容或依赖被再次编辑后，旧校验结果不能用于发布新内容。模型或工具功能样本单独显示验证范围，静态检查通过不冒充实测通过。
3. 新版本内容和快照先持久化并校验摘要，再在数据库事务内切换生效指针；失败保留旧版本生效，不出现半套新配置。可合并成“发布并启用”一次用户操作，无需额外审批流。
4. 提交任务时解析并保存完整配置引用，领取执行时再次检查可用性。排队和运行中的 attempt 固定原配置；普通编辑、发布和回退只影响后续提交。恢复沿用同一快照；请求采用新版则创建新 attempt，不修改旧记录。
5. 普通“停用”阻止新提交，已有排队/运行任务继续使用固定版本，页面清楚显示影响范围。另设“立即阻止后续调用”，在每次派发前检查，对已排队或运行任务停止相关新调用并落明确状态；在途请求尽力取消，其返回只保留为带状态的证据。停用不能撤销源端已经完成的读取。
6. 回退是把默认引用切回仍有效的已发布版本并新增变更记录；校验现有依赖与凭据仍可用。被撤销的凭据不因回退重新启用，历史 run、报告和错误记录不回滚。

普通停用、依赖不兼容和立即阻止是三种不同状态。UI、服务端和执行器使用同一规则：普通停用后不能创建使用该能力的新任务，既有任务仍可按快照调用；立即阻止后，既有任务也不能继续派发相关调用。依赖不兼容则按必需/可选性质阻止或降级受影响调用。

### 4.3 凭据与归档

凭据在页面可新增、替换和撤销；新输入只通过受认证的后端接口提交，提交后清空输入，已有值不回显。凭据不进入浏览器持久存储、AG-UI 共享状态、提示词、证据或配置导出。

首版由 `aiopsstudio-app` 在服务端加密保存凭据版本，独立主密钥通过部署 Secret/受限文件提供，不随数据库或导出包存放。配置只引用 `secret_id + version`。保存新凭据版本不会修改现有配置：轮换操作创建引用它的 MCP/模型配置版本及新的 RuntimeConfigRevision，校验后原子启用，后续提交才使用新版；旧任务沿用旧引用，除非旧凭据已撤销。旧版在运行引用释放后可清理密文，但保留历史元数据；依赖它的旧配置不再可运行或直接回退，重新绑定有效凭据需产生新配置修订。显式撤销优先于任务快照，后续调用失败并说明凭据已撤销，不自动换回旧身份。当前单租户运维账户可管理这些配置，所有接口仍鉴权并记录作者；后续多人角色划分作为扩展。

允许归档停用项，保留历史版本、工具定义和任务引用；有历史引用时不提供物理删除。配置/Skill 备份可导出脱敏包；恢复时重新绑定凭据并校验依赖。数据库、Skill 制品和证据需要一致的备份清单，独立密钥恢复材料另行保管；仅恢复数据库不能声称平台完整恢复。

## 5. 模型、可用状态与运行概览

模型配置应进入首版工作台：至少管理一个正式配置及其历史版本，支持切换默认配置。Provider、模型 ID、服务地址、认证、最大输出与实际支持的采样参数分别设置；上下文上限与工具调用能力记录验证来源，不把所有兼容 API 的参数视为相同。用户点击测试创建持久 `model_test` 任务，冻结当前配置、按幂等键提交并共享单执行槽；默认 30 秒、最多两次模型请求且每次最大输出 512 token，仍受平台上限约束。样本覆盖中文、选择确定性测试工具和接收其返回，工具回显固定非敏感内容，不读取业务数据；分别显示各轮结果、耗时和实际用量。该样本验证模型协议能力，真实 MCP 与业务理解另按场景验收，不能仅凭网络或模型列表成功判定。

每个 attempt 固定模型配置；认证失败、限额或模型不可用按统一错误/重试规则结束或交付部分结果，不静默换模型。用量按实际 provider 返回保存输入/输出/缓存 token，缺失项标未知；费用只有存在注明日期的单价配置时才估算，未知价格不能显示为零。调用、时间、token 上限由程序执行；无法精确预估的流式用量说明计量边界，在停止派发时仍保留已消耗部分。

配置可用状态至少拆成：配置已保存、协议/认证检查、样本查询检查、业务场景验收，均附时间及检查对象。Skill 详情直接列出阻塞的必需依赖和缺失的可选维度。Grafana 连通不证明指定窗口有数据，CMDB 有关系不证明来源新鲜；具体证据仍遵循总体设计的身份/时间规则。

运行概览复用已有 run/attempt/Invocation 数据，显示队列长度、当前任务、最后成功/失败、工具与模型耗时、用量、来源新鲜度及证据存储占用。故障分类至少包括模型、MCP连接、源API、参数/schema、配置变化、预算、证据存储和执行恢复；用户可以从失败项直接打开对应记录。首版先提供状态和诊断入口，持续通知策略随后按实际运维需要补充。

验收回归使用固定场景输入、独立预期检查和版本快照。升级 Skill、模型或 MCP 后按影响选择相关案例，比对首答事实、漏报/误报、证据引用、耗时及用量；不把答案注入给调查 Agent，也不要求每次文本编辑重跑所有实验。独立评测后台和自动优化平台不作为首版前置条件。

## 6. 服务端与存储落点

沿用 Node 同源入口 → Python 业务 API → PostgreSQL/受限制品存储。Node 只转接请求，Python 负责配置、校验、版本、鉴权和执行；浏览器不直连 MCP 或模型。新增管理模块不需要另建 MCP 网关、消息队列或一个执行 Agent。

| API 组（拟定） | 主要行为 |
| --- | --- |
| `/api/skills` | 列表、草稿文件、修订保存、校验、版本/差异、试运行 |
| `/api/mcp-servers` | 连接草稿、探测、工具发现与差异、版本；只改本平台连接 |
| `/api/model-configs` | 模型草稿、功能样本、版本 |
| `/api/runtime-configs` | 组合引用、发布/启用、回退、依赖状态 |
| `/api/secrets` | 只返回元数据，创建新版本/替换/撤销 |
| `/api/tool-tests` | 以固定连接和工具快照提交试调、查询/取消及显式重试 |
| `/api/invocations`、`/api/config-audit` | 调用记录、证据关联、变更历史 |

变更接口用服务端会话、同源校验及防伪造请求措施；保存带修订号，提交测试/任务带幂等键。版本和绑定表在 PostgreSQL 保存；Skill 内容按摘要存入独立持久卷，执行器只读访问已冻结内容。数据库引用制品前验证制品存在；失败中间文件按可追踪清单回收，不覆盖当前生效包。

MCP 连接池按服务、配置版本及凭据版本隔离，不能因为两个配置使用同一 URL 就混用认证会话。发布不强制断开旧 attempt 的有效连接，旧引用释放后关闭连接；撤销/立即阻止按第 4 节优先拦截。服务端运行配置保存 `config_revision`，所有调用记录关联该值及实际来源。

总体设计的 EvidenceRecord 增加 `invocation_id/purpose/config_revision`；调查调用保留 run/attempt 关联，手工试调则由独立 invocation 归属。记录接收、执行、完成/失败/取消各阶段，首版工具试调不宣称具备 Agent 检查点恢复：执行中服务重启时标记执行中断/结果未知，显式重试生成新记录，不自动伪造成功。

留存默认沿用总体设计的 7 天：调查/Skill 测试按 run 成组，独立工具或模型测试按测试任务及其 Invocation 成组清理，同时处理响应制品和索引；运行中、人工保留或仍被有效报告引用的证据暂不清理。被清理的结果保留过期元数据，不提供失效下载链接。磁盘/证据配额不足时同样拒绝需要留存的新调查、Skill试运行、工具试调和模型测试；在途任务保存有界失败记录并结束，不能只让调查入口停下而测试继续占满存储。归档配置的元数据按引用保留，不随某次调用到期误删。

## 9. 后续规划增补：发布质量、数据边界与恢复

2026-10-23 将研究缺口并入[开发路线图](development-roadmap.md)既有 R01–R13，完整契约见[可信分析与协作增量设计](可信分析与协作增量设计-v0.1.md)。本节属于未来目标，历史正文不因此变为新的已实现能力；若历史装载、发布或留存描述与本节目标不同，当前行为查 OpenSpec 主规格，未来实现采用本节与对应 change 的明确契约。

### 9.1 调整顺序与联合验收

R07 源范围及模型出站治理从 M2 提前到 M1，R01 → R02 后与 R03 并行；M1 退出包含 R01–R04 和 R07。R05 消费 R01 评估门槛与 R03 受限补读，管理入口与 R07 联合验收。R09 依赖 R05/R07/R08，在隔离 Mac 环境验证一致恢复。R13 依赖 R04/R05/R06/R07/R08/R09，Case 共享、界面与制品生命周期需要联合验收，但不必等待 R10–R12。

### 9.2 正式发布前比较新旧效果（R01、R05）

Skill、模型、MCP/schema、摘要/读取或出站策略变更按影响选择固定案例，比较旧生效版本和候选版本的事实、遗漏、错误因果、引用、覆盖、耗时、请求与成本。预期答案由独立评估器持有，不注入 Agent；门槛和适用案例在比较前冻结。重大质量退化阻止正式发布和默认切换，不能以总分或便宜抵消越权、禁止数据出站或错误确定结论。

未执行、未知、规则缺失与失败均不能算通过；未完成必需评估的版本保留草稿或显式隔离实验。实验固定内容、独立 run/attempt，不影响正式默认、历史报告与正式评分，仍受身份、出站、队列、预算和留存约束。无关的小文案改动无需全量实验。

R01 统一计量口径，R06 展示实际 token、缓存、重试、工具/源请求和耗时；缺失用量不补零。费用注明单价来源、币种、适用模型与日期，未知单价或未知用量显示未知；已知部分与总估算边界分别展示。

### 9.3 固定正文与参考文件按需读取（R03、R05）

必要正文固定加载并校验，不能只提供名称或加载失败后静默继续。大型 references 按不可变 Skill 版本的 manifest 定向读取，不再将全量参考材料作为目标行为。manifest 固定文件、摘要与大小；读取检查主体、绑定和预算，拒绝任意服务器路径、越界、符号链接逃逸、未登记文件及可变草稿。读取次数、范围、完整性、字节/token 和稳定引用可核对；必需资料未取到时明确缺失。恢复和回退不得令旧 attempt 读取新参考文件。

### 9.4 源权限与实际模型请求（R07）

服务端主体分别取得平台资源归属和上游环境/服务/对象 scope；共享源凭据不能扩大用户范围。提交、领取、每次派发、历史阅读、补读、导出与 Case 访问均核对当前授权，最新、更严格的禁止出站规则和撤权优先于快照和回退，无法继续时明确 partial/failed，不静默换模型。配置管理员不自动拥有私人内容读取权；R10 真实源接入验收需先取得 R07 权限与出站契约，Provider 与合成样本可独立准备。

目标地址/TLS 校验之外，另对平台凭据、资源身份、业务日志和用户材料定义字段允许、别名化和禁止出站规则。会话内一致别名的映射仅留服务端，不进入模型上下文、日志或普通导出；禁止把可逆编码或映射表一同发给模型。使用合成标记检查真实 HTTP payload 的消息、历史、工具 schema/返回、摘要、重试、附件和异常路径，并检查日志与导出。只测脱敏函数不能算端到端通过。

### 9.5 队列、一致恢复及共享引用（R05、R08、R09、R13）

`queue_limit` 校验、实际入队、运行概览和恢复使用同一容量规则，等待项与执行槽分开；降低容量不丢弃已持久接收项，超过新限额时拒绝新增，恢复不重复入队。该小修可提前按 R05 范围实施，本次文档更新没有修复应用。

R08 定义数据库、证据/报告附件、Skill manifest、配置/owner/共享引用和独立密钥必要版本的一致清单，密钥恢复材料单独保管。R09 在隔离 Mac 恢复，缺件或摘要/密钥不匹配明确失败；验证 owner 隔离、撤权不复活、固定快照、预算、终态、队列及制品修复不重复派发模型。不向原实例做故障注入，数据库备份存在或服务能启动不等于完整恢复。

Case 只显式发布选定报告/证据的不可变快照，按读者当前源范围交集收紧，每次读取再校验，撤回后旧链接失效；关联 Case 不隐式分享 Chat 或私人附件。R08 的引用/GC 保护有效共享制品，显式删除或过期有明确处理，不静默造成断链。人工 verdict 在 R12 另行保存操作者、依据、attempt/report/claim 版本与追加修订/撤销，不等同模型结论或用户接受，不自动进入经验库。
