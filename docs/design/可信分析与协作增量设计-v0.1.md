## 1. 目标与优先级

下一阶段先证明分析依据可靠，再完善管理、运行与协作。沿用现有 React、CopilotKit、Deep Agents、配置快照和有界只读执行，不通过增加 Agent 数量或替换框架代替质量验证。

| 阶段 | 工作包 | 退出条件补充 |
| --- | --- | --- |
| M1 把分析做准并守住数据边界 | R01–R04、R07 | 固定回放可复现；身份/窗口/覆盖、定向补读和报告核对通过适用案例；源权限、撤权与模型字段出站策略通过，未知不冒充通过。 |
| M2 让工作台稳定好用 | R05、R06、R08、R09 | 质量发布门槛、配置组合、证据导航、计量展示、引用安全和一致恢复完成相关联合验收。 |
| M3 扩展分析场景与人工核对 | R10–R12 | 只读工单、变更与候选原因查证完成各自案例；人工裁决与模型结论分开。 |
| M4 事件入口与显式协作 | R13 | 单来源告警持久接收、去重/恢复、Case、共享权限、撤回、制品生命周期及故障恢复完成整条链路验收。 |

依赖安排：

1. R01 → R02 后，R03 与 R07 并行；R04 等待 R02/R03。R07 从 M2 提前到 M1，多用户源范围和模型出站规则不能留到共享上线之后补。
2. R05 消费 R01 的回放与门槛、R02 的上下文契约和 R03 的按需补读；管理入口与 R07 联合验收。R06 基于 R03/R04 展示分析过程，恢复交互与 R09 联验；R08 在 R01 后可独立准备。
3. R09 硬依赖 R05/R07/R08，将配置、撤权、制品清单和恢复合成同一组验收。恢复不能只检查进程是否重新启动。
4. R13 硬依赖 R04/R05/R06/R07/R08/R09；共享 UI、引用和生命周期属于完整交付条件。R13 不必等待 R10–R12，M4 不是必须在 M3 全部完成后才能开始的时间串行阶段。
5. R10 的真实只读源接入验收依赖 R07 源权限与出站策略就绪；Provider 契约与合成样本可以独立准备，不提前宣称真实接入通过。

R05 的 `queue_limit` 一致性小修可先行，但需沿用该工作包的 OpenSpec 与验收记录；不因此宣布整个 R05 完成。本文没有修改该行为。

## 2. R07：主体、源范围与模型数据出站

### 2.1 一个请求具有两层授权

平台资源归属与上游源权限分别判断。服务端会话给出用户主体；自动事件使用独立、可审计的服务主体。配置管理员身份不自动授予其他用户 Chat、附件或分析案例内容的读取权。

每次源调用关联主体、连接/凭据版本、工具、环境、目标资源范围、绝对窗口和适用策略版本。使用共享源账号时，仍按当前主体的授权范围收紧查询，不能将源账号能读到的全部资源视为每个用户都可读。不能可靠收紧的工具先拒绝或明确登记为不支持该范围；模型指令、用户材料和 Skill 声明不能放宽权限。

校验覆盖手工试调、分析、补查、证据补读、历史报告、下载与导出。提交、排队领取和每次派发均核对当前授权；历史证据及其派生报告按来源范围再核对。撤权优先于历史快照，撤权后不能借旧证据、Case 或导出继续读取相关内容。在途请求尽力取消，其返回先受当前策略检查再保存/交付，不承诺收回已被用户下载的副本。

目标地址、TLS、重定向和凭据绑定属于连接安全；它们不能代替下面的数据内容出站检查。

### 2.2 分字段决定可发给模型的内容

至少区分平台凭据、资源身份、业务字段/日志和用户材料。策略明确允许、替换/缩减或禁止的字段与内容类型；未登记类型按保守规则拒绝或仅生成安全的缺口说明。不得因为 HTTP 目标可信，就把完整原始日志或用户附件默认加入模型上下文。

需要保留关联时，服务端在授权会话范围内使用一致别名，并固定映射与策略版本，以便同一对象在相关轮次中可比较。别名不采用能直接反推原值的编码；真实值到别名的映射只留服务端，不进入提示词、模型工具定义/返回、日志、普通导出或客户端可下载制品。模型输出中的别名在服务端授权展示阶段解析，不能让模型持有还原表。跨会话是否延用需显式定义，默认不建立可跨用户追踪的全局别名。

新增补查或恢复使用固定的内容快照和映射语义，同时在每次派发前执行最新、更严格的撤权/禁止出站约束；策略变化造成旧上下文不可继续时，按已取得的有效证据标为 partial 或 failed，或要求创建新 attempt，不能重新发送已被禁止的旧材料，也不能静默切换模型来绕过策略。

### 2.3 验收读取实际请求内容

在隔离 Mac 环境使用合成敏感标记，检查实际发往模型的 HTTP 请求体，包括 system/user 消息、历史、工具 schema/描述、工具返回、摘要、重试、附件和错误分支。测试只能看到可允许内容或批准别名；映射表及禁止字段不得出现。检查异常日志、事件与导出，不能只测一个脱敏函数。

双用户、共享源身份、排队撤权、运行中撤权、历史读取撤权和 Case 读者变更均有允许/拒绝案例；拒绝不泄露其他资源的内容或存在性细节。策略收紧前后复用 R01，检查脱敏是否破坏身份关联和事实质量。没有完成出站验证的配置不得被标成“数据策略已通过”。

## 3. R01 与 R05：比较新旧效果再正式发布

R01 固定案例输入、故障当时可见的源快照、独立预期、评分器和允许的结论强度。R01 完成表示回放、评分和当前版本基线齐备，不要求当前版本先通过 R05/R12 等未来能力，也不反向依赖它们。参考答案与 Agent 可见材料分离，不把事后根因或恢复结果提前提供给模型。事实正确、遗漏、错误因果、引用支持、反证处理、覆盖及诚实拒答分别计分；没有已知根因的案例不强行纳入根因正确率。

R05 在 Skill、模型、MCP/schema、查询目录、摘要/补读或数据出站策略发生相关变化时，消费 R01 的固定案例，比较旧生效版本与候选版本。比较固定配置、输入和数据，记录首次失败、重试、严格通过与分项结果、分母、耗时、源/工具请求及模型用量。按变更影响选案例，不要求无关文案每次重跑全部实验。

发布前固定适用案例、质量下限、允许的质量/成本变化与重大退化判定。越权、禁止数据出站、关键事实错误和错误的确定根因不能被平均总分或低成本抵消。候选出现约定的重大退化时阻止正式发布及默认版本切换；修复后重验相应案例并保留首败。未执行、规则缺失、失败或未知不能算通过，也不能靠删除失败案例达标。

未完成必需对比的版本可保留为草稿或显式隔离实验，不能标为正式可用。实验冻结候选内容，使用独立 run/attempt 和结果，不切换正式默认配置、不注入正式报告或评测真值；仍执行身份、出站、队列、预算和留存规则。已有正式版本因外部依赖失效而不可执行时，明确失效；“回退”不保证已经撤销的凭据或旧模型重新可用。

### 3.1 计量与费用（R01、R06）

记录实际 provider 的输入/输出/缓存 token、重试和摘要请求，区分模型请求、工具请求与源请求；按案例关联排队、执行耗时及结果。provider 缺失的用量为未知，不能补零。只有单价来源、币种、适用模型和生效/核对日期明确时才估算费用，保留估算边界；价格或用量缺失时显示未知，并分别显示已知部分。R01 规定比较口径，R06 将它展示到单轮分析与工作台，不能把一轮未知费用显示为零成本胜出。

## 4. R03 与 R05：固定正文，按需读取参考资料

必要 Skill 正文及其固定版本必须在 attempt 开始时确定性装载，加载失败不能静默跳过。参考文件建立属于该不可变版本的 manifest，包含受限相对路径、内容摘要、类型、大小和依赖关系；运行引用冻结该 manifest，不读可变草稿或任意服务器目录。

大型 `references/` 经按需读取进入上下文。受限接口只接受当前版本内的文件 ID/路径与允许选择器，检查主体、配置绑定、摘要与可读类型；拒绝绝对路径、`..` 越界、符号链接逃逸和未登记文件。若方法必需某段资料，启动或对应步骤必须取得该段；不足时标为缺失/部分覆盖，不能把没有加载当作已经阅读。

每次读取计入次数、字节/token、重复读取和总耗时预算，返回稳定引用锚点、范围与完整性。证据补读同样区分“模型只看到摘要”“保存响应已截断”“源端还有未取页”；已丢弃或源端不可得部分不能补造。R03 提供按需能力，R05 在发布、指定版本、回退和恢复组合中验证 manifest 不漂移，避免旧轮次读取新参考文件。

## 5. R13 与 R08：分析案例与显式共享

### 5.1 Case 不改变私人会话的归属

`AnalysisCase` 是事件、分析轮次与发布结果的容器，有稳定 ID、范围、事件版本和服务/用户主体。自动事件不能归入配置管理员的私人 Chat。手动分析进入 Case 时由用户选择明确报告与证据内容，不通过关联 conversation ID 自动开放聊天记录、用户附件或历史轮次。

共享对象是不可变快照：固定 attempt、报告/claim 版本、证据版本/锚点、脱敏策略版本、发布者、时间与共享修订。后续补查或新报告发布新的快照，不能覆盖旧快照内容。原始私有附件默认不在共享包中；确需分享其受限内容时，另行显式选择、检查材料归属/可分享权限并生成单独制品，不复用私人下载地址。

### 5.2 按读者范围交集发布，每次读取再核对

共享范围以被明确选择的读者当前源权限交集为上限，同时不能超过发布者可分享的材料范围。存在任何读者无权读取的内容时，拒绝该版本发布，或在用户明确预览确认后生成范围更小的新快照；不得静默泄露，也不得悄悄把全文报告伪装成完整的删减版。

发布检查不代替访问检查。列表、报告、证据片段、附件、下载与导出每次核对当前主体、Case 读者资格和对应来源范围。添加读者、源授权撤销或范围变化后重新求交集，不沿用已过期的缓存授权。无法确认权限时拒绝读取；共享链接不充当越权凭据。

用户可以撤回共享版本，服务端随后拒绝旧链接和关联下载，保留不含材料正文的必要审计。撤回共享不删除私有原报告，也不能承诺收回已被读者保存的副本。

### 5.3 生命周期联合验收

R08 对活动 Case/共享快照、报告和证据建立引用关系，保留期与回收按引用处理。被有效快照引用的制品不能静默 GC；源材料显式删除或按既定策略到期时，按已声明规则阻止删除、撤回快照或留下明确失效元数据，不能产生看似完整但依据已断链的报告。撤回读权限立即生效，不以物理回收完成为前提。

R13 与 R06/R07/R08/R09 联验：跨范围读者、私人附件、撤回后旧链接、共享期间删除/过期、恢复后撤权与重复事件均有案例。单个 Webhook 返回成功或 Case 页面可打开不等于该链路通过。

## 6. R12：人工裁决独立保存

模型报告与候选假设不直接成为人工结论。`Verdict` 保存具体判断（如确认、驳回、证据不足）、操作者服务端身份、时间、依据、适用范围，并锚定不可变的 attempt、报告与 claim 版本；操作者必须有权读取和裁决该版本。模型输出、用户点赞、关闭弹窗或“接受本次交付”勾选不能自动创建人工裁决。

人工修订或撤销追加新记录，指向被修订记录并保存原因，不覆盖旧裁决或模型报告。新报告不能继承成旧裁决已经确认，旧裁决也不在其证据失效或权限撤销后绕过读取限制。界面分别展示模型建议、检查结果与人工裁决。

允许保持证据不足，确认与驳回都需可定位依据；人工判断仍可能有错，应可审查和修订。R12 对有竞争解释、错误初判、改判和撤销建立案例，裁决可直接锚定现有 attempt/report，不必等待 R13 Case。经人工确认的内容以后可作为候选经验，但成为评估样本或经验条目前仍需审核，不能直接当真值；本轮不自动写入共享知识库、不跨用户复用私人材料。未来经验库另行定义审核、权限、有效期和回放门槛。

## 7. R05：队列限制一致性

已有静态核对发现 `queue_limit` 可配置范围与部分入队/概览固定上限存在不一致风险；本次仅登记缺口，没有运行复现或修复应用。后续用同一容量规则服务配置校验、入队判断、概览显示、恢复接收和自动事件入口。

当前单执行槽基础不变，等待队列与在执行任务分开计数；有界连接探测等控制请求仍单独计量，不能变成隐蔽的额外分析队列。降低上限后不静默丢弃已经持久接收的任务；已超限时拒绝新增并解释现状，按规则消化旧队列。恢复时不因重启重新接收同一请求或突破新接收上限，也不为满足显示值删除已有记录。具体容量上限在 R05 实现规格中统一声明。

至少验证非默认限制、边界并发提交、降低上限、概览一致、队列恢复与自动事件背压。容量不足的“已拒绝”不能同时显示为“已排队”；已接收的持久回执需有可核对的后续归宿。

## 8. R08 与 R09：一致备份及隔离恢复

R08 定义一致备份清单，关联数据库一致性点、数据库/schema 版本、任务/配置引用、证据与报告附件、Skill 版本/manifest、制品大小/摘要、保留及共享引用、身份/授权版本和独立密钥的必要版本标识。独立密钥材料单独受限保管，不进入普通数据库备份包、公开仓库或验证摘要。外部模型、源账号与远端代码不属于可由本机备份完整恢复的对象，需要重新验证有效性。

R09 在隔离的 Mac 目标用合成用户和材料完成恢复演练，不向原运行实例、数据库、配置和密钥文件写入。恢复入口先校验清单与一致性；数据库、证据附件、Skill 制品或必要密钥缺失/不匹配时失败并报告具体缺件，不以服务能启动宣称恢复完整，也不使用新生成密钥假装解开旧凭据。

恢复后验证：

1. 用户 owner、历史内容与材料引用一致；双用户不能跨归属读取。R09 先验证已交付的会话/材料权限；Case 的显式读者、撤回及其恢复属于 R13 就绪后的增量联合场景，不阻塞 R09 先行验收。
2. 配置和 Skill manifest 固定；独立密钥能解密必要的合成凭据，已撤销身份/凭据不因旧备份复活。恢复环境无法取得最新撤权状态时，不派发真实源/模型调用或开放相应受限历史，先完成授权状态核对。
3. 队列领取、已耗预算、取消、租约和终态规则可解释；旧 worker 不能覆盖新终态。结果未知时明确标未知，不自动承诺 exactly-once。
4. 已保存报告的制品修复不重复派发模型；缺失证据不被补造成正常报告。新 attempt 与安全续跑的边界各自有证明。
5. 恢复前后按清单对账，分别记录进程中断、存储缺件和一致恢复结果。尚未注入的断电边界明确未验证。

恢复演练使用隔离配置且默认不向真实源发请求；若后续确需授权的只读源或模型验证，另行记录真实调用范围，模型优先 MiniMax。没有密钥可解密的历史元数据可以用于诊断，但不能当作可运行配置或完整恢复通过。
