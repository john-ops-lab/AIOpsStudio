# M2 集成实施契约

状态：开发中；基线 main fa91b92。一个 PR 关联 #6/#7/#9/#10，四份 OpenSpec 独立验收，完成后交用户审查，未授权合并或原实例部署。

## 共享规则

- 不修改 canonical 运行副本及仓库外原配置/数据库/制品；工作目录为已有独立开发副本。测试状态/数据库/端口全部隔离，精确记录并回收任务对象。
- 统一队列上限取 settings.queue_limit；减少上限只限制新入队，已入队任务保留。模型/来源调用、排队执行耗时和已知/未知用量按 attempt 对账。
- Store 增加 query_documents(kind, *, owner_id=None, search='', status=None, cursor=None, limit=50, archived=None, include_deleted=False) -> {items,next_cursor}，数据库侧 owner/状态/时间及搜索过滤，稳定 created_at/id 降序游标。显式 query filter 可扩展，服务层不能拿全库记录后再当数据库分页。
- Store 的租约代次/fencing 由恢复模块负责；原 documents/events/worker_slot 保持兼容，新增索引/迁移必须版本化、幂等，不改原行内容。新 worker 不能采纳已失效 worker 的终态写入。
- 会话消息新增顶层 mode: analyze|explain|followup（省略保持 analyze），可提供 parent_run_id。explain 创建受预算管理的新轮、使用原授权既有材料、禁来源发现及工具；followup 始终新建关联轮，analyze 保持原兼容。主目标/窗口变更始终新轮。
- 会话列表保持 {items} 兼容，追加 next_cursor；新增 owner 内搜索/归档/恢复、JSON 导出、预览+版本绑定确认删除。下载和读取先检查 tombstone，不允许旧链接取回已删除内容。运行中或被仍保留报告引用的材料禁止删除。
- 费用端点 GET /runs/{id}/usage 返回 owner 授权的 elapsed/queue/model/tool/source/tokens/known/estimate；无单价或无完整usage时 estimate=null，明确unknown。不得硬编码供应商价格。
- 报告制品失败有 delivery_status；POST /runs/{id}/repair-report 只修复保存/消息关联，不调用模型或来源。恢复/显式重试不重置原累计用量或改写旧报告。
- 备份清单固定数据库/制品/Skill/引用版本和校验摘要，密钥另行提供；恢复到空隔离目标，缺件/错误密钥/未知撤销状态拒绝实际调用，不覆盖原运行实例。现有对象先验，Case 与人工裁决后续交付。

## 分工与集成

- 管理模块负责 config/quality/connectors 与 #6；恢复模块负责 Store/Runtime/recovery/backup 与 #10；生命周期模块负责 conversations/attachments/lifecycle 与 #9 及消息mode桥接；主集成负责 Web/#7、API装配、文档、资源监测、真实模型/浏览器/PG联合验收和PR。
- 每个共享文件仅一个负责人编辑；需要跨模块改动先消息对齐，由该文件负责人落盘。所有负责人先完善自己 OpenSpec 设计再实现。
