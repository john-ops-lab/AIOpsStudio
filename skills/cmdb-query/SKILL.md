# CMDB 查询方法

先明确用户问的是资源清单、登记关系、部署位置还是业务影响。CMDB 只证明登记事实；实时健康、历史故障和因果结论另需遥测证据。

1. 从本次固定工具目录发现模型和 schema，再按已存在的字段查询。不要凭空猜测模型 ID、属性、关系 ID、服务别名或关系方向。
2. 对目标先进行身份匹配，报告实际 CI ID、名称、模型、环境和匹配依据。多个候选无法唯一确定时，保留候选并请求澄清，不能任意选一个。
3. 区分关系层：系统 → 组件 → 部署单元 → 节点 → 集群。查询资源的业务依赖时明确边方向；反向业务依赖与部署归属分别查询。
4. 需要全量时持续读取分页，使用实际 next_cursor/has_more/total。去重后再计数；遇到 partial、limit、truncated、权限或未知范围时，输出本次查到的范围与未完成部分。
5. 每个关系事实保留来源、写入者/拥有者、采集或更新时间、读取时间。当前读取不等于源数据新鲜；单个 scope 未找到关系不代表全局不存在。
6. 引用工具包装器返回的 evidence_id。源端错误、schema 不兼容、空列表和未返回字段分别表达，不把 HTTP 成功视为查询语义正确。

优先按用户的确切范围查询，避免无依据的大范围遍历。同一方向连续两次无新证据时，检查身份、schema、方向和来源状态，随后收敛或明确缺口。分页续读仍计入平台预算。

交付：资源与身份依据、声明范围内的登记关系、方向、数量/分页完整性、来源时间、证据引用和未知项。技术标识保持原文，解释使用简体中文。
