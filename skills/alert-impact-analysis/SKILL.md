# 告警影响分析

输入必须包含告警 ID 或明确目标、环境，以及带时区的 analysis_start / analysis_end。平台已冻结本次正文、配置和窗口；补充消息不能静默改变主目标和主窗口。

1. 读取 Ongrid 告警详情与时间线；记录告警状态、触发/恢复时间、原始标签和信号。告警名称不直接等于服务名。源系统自动分析报告只能标为外部分析，不能当作独立证据。
2. 按固定 CMDB 方法发现 schema、匹配 CI 身份，分别核对系统、组件、部署单元、节点、集群的登记关系。明确匹配依据和歧义，不根据名称相似度直接合并实体。
3. 从故障资源反向查业务依赖，保留关系方向、层次、来源与更新时间。登记依赖只作为潜在影响范围；权限、分页不完整或来源过期时标明范围。
4. 发现真实 Grafana 数据源及其 UID、已有指标/日志标签和 Trace 查询能力，再对固定窗口查询。不得凭空猜测数据源 UID、PromQL 指标或服务标签。使用绝对时间，查询参数不得扩大窗口。
5. 对相关服务检查有依据的错误、延迟、吞吐、资源指标，并按需要查看日志/Trace。保留查询式、数据源、窗口、原始返回与 evidence_id。缺少监控数据不是服务正常，未采集 Trace 不是请求未发生。
6. 将「CMDB 登记的潜在影响」「窗口内已观测异常」「可能原因」分别列出。时间相关性不能单独确认因果；节点共置、同 kind 集群不等于物理隔离或共同故障原因。
7. 同一方向连续两次失败或没有新证据后，检查身份、标签、数据源和窗口，选择有依据的新方向或停止。遵守工具、请求、时间和 token 预算；失败不自动换模型，不使用 Shell 兜底。

最终中文报告包括：本次窗口（Asia/Shanghai 展示且保留源时间）、目标和身份依据、告警时间线、潜在影响、已观测影响、支持与反驳证据、未知项、下一步验证。每个重要结论引用已取得的 evidence_id。没有证据时明确说未确认，不虚构服务数量、故障恢复或根因。

GLPI 尚未接入，工单/变更维度标为未查；此可选维度不阻止其他分析。报告成功只表示完成本次声明范围，不代表故障恢复或业务验收通过。
