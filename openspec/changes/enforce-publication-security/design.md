# Design

## Context

目前只有依赖运行配置的人工秘密扫描脚本，不能作为通用 Git 门禁。参见 proposal 的动机。现有公开图片已完成 OCR/目视及元数据清理；原运行实例必须保持不变。

## Goals / Non-Goals

覆盖暂存快照和所有实际推送对象的可达内容；检查失败时阻止正常 Git 操作，并提供可复现测试。门禁是客户端发布保护，不声称阻止拥有本机控制权的人主动绕过钩子；GitHub Push Protection 保持开启，CI 作为远端复核，不能代替推送前保护。

## Decisions

1. 版本化 `.githooks/pre-commit`、`pre-push` 调用同一 Python 标准库扫描入口。安装器仅修改公开副本的 local Git 配置，拒绝覆盖其他钩子；新克隆需要执行安装命令。
2. 提交使用 `git write-tree` 获取索引树；推送读取 Git 的 ref 更新输入，扫描目标对象的全部祖先、各版本 blob、ref 名称和 commit/tag 元数据。使用临时快照交给 Gitleaks，不依赖工作区、远端基线或历史 diff 的删除行；任何对象类型/尺寸不能完整检查时阻断。手动 history 模式覆盖全部 refs。
3. Gitleaks 强制内置默认规则，忽略环境/行内放行，禁用仓库外隐式忽略；输出仅解析后的安全字段。额外结构规则识别私网地址、本机 home 路径、内部域名，文件路径规则拒绝凭据、配置和运行资料。合成示例不得用宽泛目录例外放行。
4. PNG 允许列表绑定相对路径和 SHA-256，要求必要块、CRC、无尾随数据；任何其他未知二进制/嵌入媒体默认拒绝。允许列表更新意味着明确人工复核，不能自动将新图标为已审。
5. 当前副本配置仓库外、权限受限的私有 profile，只保存来源描述和现场规则，不复制实际密钥。只读 helper 从 JSON/文本文件及本机 PostgreSQL/Fernet 来源提取，在管道内传递给扫描器；不导入 deploy.env/Store，不写运行配置，不连接非回环数据库。缺 profile（已配置时）、缺依赖或来源失败均阻断。CI 不持有私有 profile，但执行相同通用规则。
6. GitHub Actions 使用最小只读权限和固定版本依赖，完整检出后运行历史扫描及合成回归；不上传原始扫描报告、上下文词表或实际凭据。检查脚本不提供 SKIP 环境开关。

## Risks / Trade-offs

- 任意业务名称/数字不能被通用规则可靠识别 → 本机私有现场规则补充精确匹配，图片及二进制采用复核清单；文档公开前仍审查实际差异。
- 钩子可被人为禁用、无法随 clone 自动生效 → 安装步骤进入首次开发流程，CI 和 GitHub Push Protection 复核；不虚报服务端可强制所有现场规则。
- 全历史扫描增加耗时 → 按 blob 去重，批量读取对象；不牺牲范围完整性，首版仓库规模允许。
- 检查器日志本身泄露 → 不打印匹配文本/原始异常/来源路径，路径做 JSON 转义、已知值替换和高风险名称摘要化。

## Migration Plan

先实现并用临时 Git 仓库/本机 bare remote 验证拦截，再安装到公开副本，配置仓库外私有来源并扫描自身。通过实际钩子提交和推送，核对 GitHub CI；不改变原运行目录或全局 Git 配置。恢复只需按文档恢复此副本先前 hooksPath；任何关闭保护均需明确操作，不由脚本自动降级。
