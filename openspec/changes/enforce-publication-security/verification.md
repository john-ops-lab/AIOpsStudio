## 首次失败与修复

首轮 17 项测试中 4 项失败：内部主机规则误把 `.local.json` 当作主机；IPv4 文件名后接扩展名时漏检。首次历史试扫还发现大小写不敏感的 home 路径规则误报 `/api/users`，以及 Python `deploy.local` 导入误报。修复规则边界并增加路由/模块/文件名正反用例后，上述问题消除。

图片审批记录也改为从实际暂存树或已提交 HEAD 读取，避免工作区里未暂存的批准记录提前放行。首次引入清单、尚未提交时，history 模式按设计因 HEAD 无清单而拒绝；暂存检查通过后才能提交清单并进入历史检查。

CI 从固定官方 Go 模块版本构建 Gitleaks，显式设置其版本字段，防止开发构建的默认版本字符串被版本门禁拒绝。工作流使用完整历史、只读权限和固定 checkout 提交；不持有私有 profile，不上传扫描原始材料。

首次远端 CI 在安装步骤失败：Mac runner 未预装 Go，扫描步骤未执行，不能计作通过。修复为固定 SHA 的 setup-go 显式安装工具链后重新验证。

旧 `known_secret_values()` 验收入口保留，但改用只读来源采集；仅返回凭据，不将公开配置实体 ID 当成 API 泄露。真实私有来源兼容核对：72 项凭据集合与旧采集基准一致，不打印内容；发布扫描额外包含配置实体标识，共 88 项。

## 发布与剩余边界

实际提交/推送和远端 CI 结果将在执行后记录。CI 是上传后的通用复核，本机私有比对是上传前的额外保护。客户端钩子可被主动关闭，新 clone 仍需安装；不把扫描通过表述为所有自定义名称、编码和图片像素均可自动识别。图片清单继续要求人工目视/OCR 复核。
