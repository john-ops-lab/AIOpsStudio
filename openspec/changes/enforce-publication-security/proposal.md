# Proposal

## Why

人工扫描无法保证每次提交和推送都覆盖实际上传内容，尤其会漏掉暂存区差异、已删除的历史泄露和图片。需要将公开发布边界变成日常 Git 流程的可验证门禁，保持现有运行实例不变。

## What Changes

- 提交前检查暂存快照；推送前按 Git 提供的目标对象检查完整可达历史，包括其他分支、标签和中间提交。
- 使用 Gitleaks 默认规则，补充本机路径、私网地址、内部域名、运行配置/数据文件和二进制资产规则；缺依赖、无法完整读取或检查失败均阻断。
- 可配置仓库外的私有规则及只读凭据来源，自动比对实际凭据和现场标记；不在仓库或日志中保存原值。
- 新增图片以精确内容哈希绑定人工/OCR复核；未复核二进制和嵌入式媒体默认阻断。
- 增加安装入口、独立检查命令、GitHub Actions 和合成 Git 回归；仅在独立公开开发副本安装钩子。

## Capabilities

### New Capabilities

- `publication-safety`: 公开提交/推送的内容与历史门禁、私有来源保护、资产复核及安全诊断。

### Modified Capabilities

无，工作台业务 API、用户数据和执行行为保持不变。

## Impact

新增 scripts、Git hooks、安全策略/文档和 CI；Git 客户端需要 Python 3 与 Gitleaks。当前工作副本配置本仓库专用钩子与仓库外私有扫描资料，原运行源码、凭据、数据库及进程不改动。不调用模型或源系统，不创建标签或 Release。
