# Proposal

## Why

用户要求对公开仓库的个人路径、现场接口与部署标识、真实实验数据和可关联记录全部脱敏，覆盖图片及 Git 历史，重新推送后复扫。清理必须在独立副本完成，保持本机现有配置、数据库、凭据、代码和进程不变。

## What Changes

- 公开源码通过外部配置读取部署与引导信息，移除现场地址、私有工作区依赖及固定部署指纹，使用通用默认值和明确合成示例。
- 文档和 OpenSpec 保留需求、方法、结果计数及失败边界；现场标识、样本值、原始记录 ID/哈希和个人路径改为说明或审查别名。
- 原型和架构图片重新制作成独立演示素材，清除元数据，并进行本机 OCR 与人工复查。
- 建立不含旧提交祖先的公开历史，推送前后检查所有公开 refs、完整历史、图片和附属内容，并单独检查旧对象可访问性。
- 对本机运行目录、私密配置和进程做前后指纹比对，不在原运行目录实施迁移或重启。

## Capabilities

### New Capabilities

无。此变更为公开数据清理、部署配置重构与历史发布，不新增工作台业务能力。

### Modified Capabilities

无。`.openspec.yaml` 设置 `skip_specs: true`；用户会话、附件、权限和只读执行的既有规格保持不变。

## Impact

仅修改独立公开副本的源码、文档、设计资产和 Git 历史；影响 GitHub main 的提交标识。原运行实例保持原目录、配置及进程。模型相关测试优先 MiniMax，本次不需要真实模型调用或源系统写入。
