# Design

## Context

见 proposal 的 Why。公开内容中包含实例定位和验证关联信息；运行实例与公开源码目前共用来源，因此不能直接在运行目录批量替换。历史改写只改变可达 refs，并不自动保证 GitHub 旧对象缓存被清除。

## Goals / Non-Goals

目标是提供通用公开源码和不含实例信息的设计/验证材料，并移除公开可达历史中的原始版本。保留实际验收结果计数及首次失败事实，不把重新制作的演示图当作在线验收截图。

本次不迁移运行实例、不轮换凭据、不修改数据库、不重启服务；原始设计和验证原件仅保存在私有工作区。通用协议字段、产品默认账户、依赖版本/校验和与合成测试不是实例数据，按功能和可复现需要保留。

## Decisions

1. 使用独立公开 checkout 实施；保存原运行源码、私密文件、配置记录和进程身份的私有指纹，在结束时比对。
2. 现场源连接、Docker context、SSH 转发与监听参数从用户提供的外部配置读取；公共默认值不复用现场约定。参数测试只使用本机临时目录和合成配置。
3. 文档以“审查别名”替代真实运行和证据标识，以方法和检查结果替代现场样本值；删除真实内容/收据摘要和私有工作区索引。依赖完整性哈希保持原样。
4. 所有公开 PNG 用通用演示素材替换，画面不复用现场标签和数值；去除 PNG 生成来源与其他非必要元数据，复查图像内容。
5. 将脱敏后的完整树提交为新根，不保留任何原提交为祖先；只更新 main，并用精确 lease 避免覆盖扫描期间的其他工作。旧对象及其标识保留在私有审计中，不写进公开修复记录。
6. 推送后重新克隆 GitHub refs，扫描完整对象、图片与附属面；再请求旧 commit/blob URL。若 GitHub 仍暴露旧对象，明确区分已完成的可达历史清理与待平台清除的残留，不能将 force push 成功当作完全删除。

## Risks / Trade-offs

- 历史摘要与现场内容的联系 → 原始证据在私有目录保留；公开验收明确是去标识摘要，不伪造新的在线结果。
- 旧 checkout 可能重新引入旧历史 → 公开维护使用新 checkout，原运行 checkout 不用于向公共库推送。
- GitHub 旧对象缓存仍可访问 → 根据[官方移除说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)核查，必要的平台处理或扩大仓库操作在实际确认残留后提出，不虚报完成。

## Migration Plan

完成独立副本脱敏与相称测试，先扫描再重建公开根提交，推送后重新扫描和核对本机保留指纹。保留私有恢复材料；不将它们作为公开分支或标签发布。

## 2026-10-23 补充授权与处理

用户已明确授权删除并重建同名公共仓库、重新上传和全面复扫，并要求出现认证时打开页面由其完成。操作仅限 GitHub 仓库及独立公开 checkout；原运行目录、配置、数据库和进程保持不变。

删除前重新核对仓库身份、全部 refs、附属内容和恢复 bundle，记录本轮运行实例指纹。删除后创建同名 Public 仓库，推送已脱敏历史并核对 MIT 与原有安全设置；独立重新克隆做全文件、完整历史、图片和附属面扫描。匿名请求所有已知旧提交、源码和原图入口，只有确认不可访问才能关闭残留任务；缓存或网络失败不能当作删除成功。
