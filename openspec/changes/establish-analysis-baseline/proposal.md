# 建立独立分析案例与当前版本基线（R01）

## Why

现有协议测试证明队列、工具与模型可连接，但不能独立判断事实、遗漏、错误因果和范围声明。M1 必须先固定输入及不向 Agent 披露的答案，再测量当前版本；未来能力失败保留，不能通过移除案例使基线通过。

## What Changes

- 增加公开、无现场数据的合成案例及独立 oracle。最初 legacy 套件为 15 案例/88 断言并保持冻结；另增 `evaluation/m1/` 的 18 案例/105 断言，同套件分别测量旧版与候选版。
- 增加确定性评分器与从真实 FastAPI `/api/runs` 入口回放的隔离 CLI。合成模型只读实际模型上下文，合成源只返回案例中声明当时可见的数据；两者均不得读取 oracle。
- 冻结 `bd9a949` 源码基线，以及模型、Skill、schema、摘要器、查询、隐私策略和评分器版本/内容摘要。候选版复用同一案例与冻结配置，不能覆盖首轮基线。
- 输出严格通过、各维度分子/分母、失败分类、首败/重试、未验证、耗时和用量未知项；未知不按零或通过计算。
- M1 合成回放保留真实 ChatOpenAI SDK 和应用 HTTP 出站守卫，仅替换 HTTP transport；登记固定合成身份、查询和类型字段策略，未知字段继续拒绝。可显式引用仓库外 `0600` 配置进行 MiniMax + 合成源测量。
- 包含正常、缺失/陈旧、第二序列/尾部、分页、歧义、源失败、模型失败、无关证据与出站、共享/撤权、裁决、references、一致恢复边界。尚未实现的能力明确失败或未验证。

## Impact

本项仅新增评估模块、合成文件、OpenSpec 与专项测试；应用能力变更由其他 M1 change 管理。默认执行不联网、不读取真实模型配置、不访问生产数据库，不启动常驻服务或修改原实例。显式真实模型测量优先 MiniMax，配置只在子进程内使用，原始观察仅保存在仓库外。

已取得同套件可比结果：M1 旧版严格 7/18，候选 15/18；候选 102 passed、0 failed、3 unknown。共享撤权、人工裁决和一致恢复仍保留在分母中。三次真实 MiniMax + 合成源尝试保持 failed/partial；本轮未连接真实业务源或重新验收真实案例，不能将这些结果称作业务验收。
