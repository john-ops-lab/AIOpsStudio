## Context

配置已有不可变发布、乐观并发及目录发现基础，但实际发布未消费固定质量评估，MCP 目录和依赖组合、Skill 制品路径、设置/入队/概览的一致性仍有缺口。本次与 Chat、生命周期及恢复组成一个 M2 集成 PR。

## Decisions

1. 新发布默认 formal，必须携带服务端保存且当前有效的质量评价。旧已发布版本不改写；experimental 只新增不可变实验版本，不修改 current_version、启用状态或默认选择。回退不能选择实验版本，也不能复活已撤销凭据或立即阻止状态。
2. 质量 API 只接收服务端已保存的 candidate_run_ids/baseline_run_ids，不接受客户端 pass、score、observations。固定 suite/scorer 和关键门槛由代码版本提供，服务端从实际终态 run、配置快照、调用记录、证据和守卫计数计算。未知关键检查、未执行或重大退化拒绝正式发布，费用/上游内部请求未知单列。
3. candidate_binding 固定候选可执行字段及 references、所选依赖/模型、源/出站策略和设置的摘要；测试开始由执行器保存 binding，评价与发布时再次核对。候选内容、依赖、策略或模型变化即失效。非首版必须提供 current_version 的同输入/同源快照实际基线，首版使用明确的固定协议约束基准，不伪造旧版数据。
4. model_test 核对实际 SDK 中文工具两轮；skill_test 核对实际模型报告、证据引用和确定性结构事实；MCP tool_test 核对实际守卫派发、保存响应及已完整发现的工具定义。服务端调用/证据缺失不能用 run.status 代替。评价仅保存安全摘要和稳定引用，不复制源正文、凭据或推理。
5. 修改/发布/回退/状态操作使用事务与 expected_revision；普通停用只拒绝新任务，立即阻止和凭据撤销在后续派发前优先。queue_limit 配置维持原上限，所有消费者使用当前设置，降低上限不取消已有任务。
6. Skill 包仍为受限正文与 references，不导入脚本或依赖。规范路径、重复归一化路径、符号链接和不可变制品冲突拒绝；制品先在本根目录暂存并原子激活，异常只回收本次新建暂存目录。
7. MCP 完整发现与工具 schema 摘要绑定；重复名称/别名、未审核只读、目录变化或不兼容必需依赖阻止发布。可选依赖仅产生明确 warning，不扩大白名单。
8. 模型 pricing 为可选的版本化元数据，单价不得为负或非有限数值。缺少用量、价格或缓存单价的费用保持未知；价格未知不冒充质量检查通过，也不阻止无该计费维度的 MCP 交付。
9. JSON Schema 使用统一离线验证模块。按 referencing.Resource.subresources() 的规范节点遍历检查 $ref/$dynamicRef，不遍历 examples/default/const/enum 等实例数据；仅允许本地片段引用。配置静态检查、MCP 目录和实际参数验证、Skill 实际输入验证都显式使用禁止检索的 Registry，旧已发布 schema 也不能触发网络或文件读取。本地 $defs、锚点和动态锚点继续按 JSON Schema 规范解析。

## Validation

Mac 上运行定向合成回归，使用同一个 scorer 验证服务端已保存的真实管线记录；旧 fixture 的种入只允许明确的测试 helper，生产没有绕过开关。覆盖绑定漂移、未知/首败、实验隔离、并发、目录和依赖变化、撤销及路径逃逸。真实 MiniMax 自主补读和 PostgreSQL/浏览器联合验收由主集成完成，不能把 QA 补读当自主成功。

## R01 双门槛连接

`release_baseline.PipelineQuality` 固定执行既有 `scripts/evaluate_analysis.py` 的原始 bd9a949 基线和 M1 当前候选，不接受路径、live-model-config、case 过滤或 JSON 评分导入。受控子进程清除凭据/原配置环境，使用外部临时目录、300秒上限，数据库原子锁跨进程串行，进程组仅绑定本次 Popen；资源不足不启动，收尾删除本轮临时材料。开始/结束实现摘要及 runner 冻结副本摘要必须一致。

正式发布为双门槛：R01 独立事实/遗漏/因果/覆盖/引用/边界断言零失败且既有通过项不退化，加上本配置候选/当前版实际试运行的协议、声明结构事实、权限、源快照及资源比较。原固定适配器尚不能执行的 Case 共享、人工裁决、一致恢复三条命名检查仅作为 out_of_scope unknown 留在105分母，不视为通过；R09 一致恢复另由本 M2 隔离验证提供证据。其他未知均阻断。前者衡量固定合成管线，后者限于已观测配置契约，不宣称覆盖全部自然语言质量或真实业务根因。

API：GET/POST `/api/quality/pipeline`，POST仅接受空对象；三个配置种类 GET/POST `/{id}/quality`，POST只接受 expected_revision、candidate_run_ids、baseline_run_ids；发布接收 channel 和 evaluation_id。pipeline 当前实现证明可跨配置复用；任何实现变化要求重新回放。当前配置试运行使用服务端生成的 quality_binding，不能由客户端指定。

## Astra 本地复审补修

案例身份只含执行输入，候选与当前正式基线双重版本绑定。评价/发布的哈希和制品准备移至工作线程及事务外，最终只短锁核对内部预检和状态；回放指纹覆盖辅助实现及实际材料，全组安全回收后才解锁。

Astra 补审进一步要求最终事务无递归文件扫描或 metadata 查询：锁外最后核验后生成短时有效的服务端提交票据，Store 锁内只做票据有效期与数据库 CAS，Skill 仅保留必需的原子激活及回滚。外部进程直接改文件存在文件系统与数据库间的固有窗口，不把票据描述为跨系统原子提交。
