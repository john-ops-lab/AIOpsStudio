# Design

## Context

现有首版已具备 Chat、私有资源归属、配置发布快照、证据和预算；这次修订补齐后续工作包的验收契约。当前行为以主规格为准；未来契约见新增量设计，不能用规划勾选代替业务验收。

## Goals / Non-Goals

**Goals:** 保持一个总路线图和十三个工作包，将每个已确认缺口落到主责、配合方、可观察验收和发布门槛；远端 Issue 与正式文档一致。

**Non-Goals:** 本次不实现产品功能，不发布版本号或日期承诺，不修改主规格、原运行实例、配置或数据库，不新建 Issue、标签或 Release。

## Decisions

1. R07 从 M2 调整为 M1，在 R02 后与 R03 并行。M1 退出包含 R01–R04 及 R07；不同权限团队使用前必须通过源权限和模型数据出站验收。
2. R01 冻结当前案例基线和评分口径；R05 消费它进行按影响的新旧版本比较和正式发布门槛。R01 不等待未来能力通过，R05 不反向等待 R11/R12，避免质量门槛形成循环。
3. R03 负责已存证据与固定 Skill 版本清单内参考资料的受限补读；两种资源类型分别鉴权和定位。R05 验证版本、必载正文与发布质量，R06 提供证据、补查及费用入口。
4. R12 人工裁决锚定 attempt、报告与结论版本，独立于模型输出和用户接受状态；不以 Case 或经验库为前置。R13 负责 Case 显式共享，消费 R07 权限、R08 引用生命周期和 R06 操作入口，不隐式共享私有 Chat/附件。
5. R05 统一 queue_limit 配置、入队和概览语义；小修可先准备，但正式闭项仍满足全部验收。R08 定义备份引用清单，R09 在隔离 Mac 验证一致恢复和旧执行器隔离。费用计量由 R01 定义、R05 核对、R06 展示。
6. 保留全部原始交付范围，Issue 仅替换授权的标题/正文，保留 state、labels、assignees、milestone 及讨论。写前读取最新快照，发布前检查准确字节，写后比对读回；远端出现新编辑时先协调，不静默覆盖。

## Risks / Trade-offs

- [范围增加导致闭项模糊] → 每个增量进入现有范围和验收清单；先行小修不代表整个 Issue 完成。
- [共享或恢复出现反向依赖] → R09 单向消费 R08，R13 单向消费 R06/R08；R08 不等待 Case 开发。
- [规划被误读为实现] → 主规格不变，实施项保持待实施，文档记录仅为本次发布验收。
- [公开规划含私有内容] → 准确 Issue 快照与实际暂存树使用现有安全门禁，私有比对仅通过只读 helper，不发布现场研究索引。

## Migration Plan

无运行迁移。先生成具体修订、检查依赖无环和读者可理解性，再完成 Issue 与文档同步、正常提交推送及当前提交 CI 核对。后续每项实现分别创建 OpenSpec 变更。
