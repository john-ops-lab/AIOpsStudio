# Spec Delta

## Purpose

为运维用户提供以自然语言会话为中心的持续分析工作区，在同一会话中组织上下文、多轮执行、报告、原始证据和附件，使用户能够清楚理解每轮结论、数据缺口以及后续补查的关系。

## ADDED Requirements

### Requirement: 产品入口与文案一致
系统 SHALL 将主入口命名为“运维工作台”，将用户可见的运维“调查”文案统一为“分析”。侧栏 SHALL 展示当前用户与账号操作，不显示“Mac 本地”“本机工作空间”等绑定部署主机的文案。已有内部 API 标识保持兼容。

#### Scenario: 登录后进入工作台
- **WHEN** 用户成功登录
- **THEN** 默认进入可输入消息的运维工作台，侧栏提供 Skill、MCP、模型等入口及当前用户信息

### Requirement: Chat 与分析画布并列
系统 SHALL 以 Chat 为主区域，桌面采用侧栏、对话、可折叠分析画布；画布提供报告、证据、执行记录。窄屏 SHALL 优先保留 Chat 和可操作输入框，通过显式控件打开画布。

#### Scenario: 查看报告中的证据
- **WHEN** 用户选择分析回复的报告卡片或证据引用
- **THEN** 页面打开对应轮次的报告或同 ID 原始证据，Chat 会话和输入内容保持不变

### Requirement: 上下文可见且缺失可补充
系统 SHALL 在对话中显示当前 Skill、目标或告警、固定分析时间窗等上下文；允许从告警或 Skill 页面携带上下文进入。缺少执行必需输入时 SHALL 保存用户消息并明确需要补充的字段，不伪造已开始的分析。

#### Scenario: 未选择必需 Skill
- **WHEN** 用户发送问题但尚无可用 Skill 或所需分析时间窗
- **THEN** 会话保留问题和明确的补充提示，数据库不创建无效执行；补齐后可显式再次提交

### Requirement: 持续对话与独立分析轮次
系统 SHALL 在一轮分析结束后保持输入框可用；继续追问创建同会话的关联新轮次，保留前轮报告、消息与证据。新轮次 SHALL 获取有界历史上下文，并明确区分历史材料与本轮新证据。运行中上下文未变化的补充消息投入当前轮，主目标、Skill 或时间窗变化产生新轮次。

#### Scenario: 终态后继续追问
- **WHEN** 用户在已完成的会话发送补查问题
- **THEN** 新建关联前轮的执行；旧报告不被覆盖，新轮上下文包含前轮问题和报告摘要，旧证据不自动成为本轮证据

### Requirement: 发送和恢复幂等
系统 SHALL 以当前用户、会话与客户端消息标识保证重发只生成一条消息及至多一次对应执行。刷新、切换和流重连 SHALL 恢复持久状态，不能创建新执行或取消原执行。

#### Scenario: 网络重试同一条消息
- **WHEN** 客户端使用相同 client_message_id 重发已受理消息
- **THEN** 返回原有消息与执行收据，不新增分析轮次

### Requirement: 可读状态与键盘操作
系统 SHALL 分别表达执行状态与覆盖程度，显示真实失败及未知范围。报告、证据、画布与附件操作 SHALL 可通过键盘完成，弹窗关闭后恢复焦点；实时消息更新不抢走输入焦点。

#### Scenario: 部分覆盖的分析完成
- **WHEN** 分析已结束但部分依赖或信号未覆盖
- **THEN** 界面显示本轮完成及部分覆盖，保留待补查信息和可用的继续追问输入框
