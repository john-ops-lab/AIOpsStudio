# Proposal

## Why

当前工作台将 Chat 放在任务详情的附属区域，任务结束后不能直接继续追问；单管理员身份也无法隔离不同用户的服务端历史和附件。需要按当时确认的界面要求完成可连续使用的运维工作台。

## What Changes

- 主入口统一为“运维工作台”，用户可见工作流中的“调查”统一改为“分析”；去除侧栏“Mac 本地”“本机工作空间”等部署环境文案，改为当前用户信息与账号操作。
- 以会话为主线实现左侧历史、中间 Chat、右侧报告/证据/执行记录；持续显示输入框，完成后追问创建关联新轮次。
- 增加服务端用户账号、角色、持久会话和 owner 隔离。管理员管理账号与配置，普通用户可分析并读取自己历史；管理员也不能默认读取其他用户私有对话。
- 持久保存用户附件及分析产生的报告文件，提供受归属校验的上传/下载。文本附件有界作为用户材料进入上下文，二进制附件可保存下载，能力边界明确。
- 初始化 OpenSpec，补入现有执行边界基线；本次功能按规格、任务、实现、验证闭环交付。
- 保持已有 API 技术标识与管理员口令登录兼容；历史未标 owner 的数据仅归 admin。

## Capabilities

### New Capabilities

- `chat-workspace`: Chat 主入口、会话历史、上下文、连续轮次与分析画布，统一产品文案。
- `user-history`: 真实用户身份、账号管理、私有会话与运行数据的服务端归属和兼容迁移。
- `conversation-attachments`: 用户附件与生成报告的持久存储、授权下载和文本材料上下文。

### Modified Capabilities

无。`managed-readonly-execution` 为已有实现的补录基线，不改其只读、冻结配置和单执行槽要求。

## Impact

影响 FastAPI 认证/API、新会话及附件服务、runtime/AG-UI 的归属与连续轮次、React 工作台与账号界面、Node 同源适配、文档及相称测试。正式数据仍用 PostgreSQL，文件在服务端持久目录。所有开发、部署和验证仅在 Mac；不修改 外部数据源。GitHub 更新、公开发布、SSO、多组织租户、自动修复与任意文件执行不在本次范围内。
