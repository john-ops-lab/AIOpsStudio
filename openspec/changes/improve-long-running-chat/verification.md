# #7 长流程聊天验收

本项在 Mac 隔离实例验证，未写原配置、对话或附件。统一证据与首败见 [M2 集成验收](../../../docs/validation/2026-10-27-m2.md)。

- 显式 analyze/explain/followup 与同会话父轮、幂等持久受理、processed/unprocessed 状态、独立预算、原报告保留均有 API 定向回归。
- 真实 MiniMax 解释：1 次模型请求，工具/源/MCP 请求均 0，父轮报告/用量不变；引用可在浏览器跳转到原分析轮次与已保存片段。
- 真实 MiniMax 补查：新 run/attempt 和新证据，3 次模型请求，原轮次报告和用量不变；额外未核验结论保留 partial，不作为已确认事实。
- 连续解释对 canonical reference_run_id 逐节点重新授权，环、跨会话、删除后拒绝；缺 history 出站字段的原策略拒绝且零派发。
- 用量 HTTP 仅返回拥有者投影、读取原固定价格；外部用户/删除记录拒绝。缓存缺件、非法类型、负数、超总量、缺单价或供应商未知重试均不伪造零费用。5 项直接用量回归通过，真实回执与实际模型请求数一致，真实价格未配置因而显示未知。
- Chrome 桌面已核对三轮消息、模式选择、解释引用父轮导航、附件容量、删除预览和归档/恢复；390×844 分析画布用量可读、无横向溢出，随后恢复默认视口。未在页面发起额外模型调用。
- 完整回归、构建、OpenSpec 和源/模型实际调用分别记录，不把 MockTransport、手动阅读或 synthetic scorer fixture 说成真实 MiniMax 自主能力。

## 首败和修复

中途发现连续解释只引用直接父轮的空 evidence；修为逐跳定位并重新授权原证据。费用回执异常可能抛错或显示假零，补有效性校验和未知态；恢复未授权 503 清除页面缓存。解释轮在页面显式显示“解释已有结果”，补查显示独立轮次名称。原失败与后续通过均保留于私有证据，未修改冻结 M1 oracle。
