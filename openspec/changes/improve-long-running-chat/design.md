## Context

区分解释已有结果和补查新证据，明确消息状态、父轮、独立预算，改善证据导航、重连和用量费用显示。

## Decisions

解释模式不发现或调用来源工具，只使用重新授权的既有材料；补查创建关联新轮且保持旧报告。未知用量或单价显示未知，不虚构费用。

共享接口先以 docs/design/M2集成实施契约.md 为准；本 change 负责人在实现前补齐设计细节和异常语义。

## Validation

按 Issue 逐项验收，使用隔离数据；保留首败、未知和真实 MiniMax 自主操作的边界。资源受限时及时结束本轮临时进程、容器与无用文件，不清理无关项目。

## API 与交互

消息顶层 mode 默认为 analyze，explain 仅解释有 parent_run_id 的既有授权材料，不提供来源目录/工具；followup 强制关联新轮。前端显式选择操作，不凭自然语言猜测。错误/accepted/processed/unprocessed 状态沿用持久收据，并展示重连、取消、重试和制品修复入口。

GET /runs/{id}/usage 重新核对 owner 和最新材料权限。展示排队/执行秒数、逻辑/实际模型请求、工具/源请求、完整或局部已知 token、缓存回执和未知重试；仅存在完整用量及含版本/日期/币种的单价时计算估价。缓存有量无价则估价未知，供应商内部重试不补零。价格不硬编码，来自本轮固定配置。

历史侧边栏使用服务端 search/archived/limit/cursor分页，用户显式加载下一页；会话和附件提供预览确认删除、归档恢复、导出、容量与失效状态。共享/人工裁决入口不提前提供。
