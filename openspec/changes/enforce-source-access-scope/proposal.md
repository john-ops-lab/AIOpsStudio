## Why

现有 owner 隔离保护私人历史，但共享数据源凭据的读取范围尚未绑定当前用户，业务数据也没有独立的远程模型出站策略。M1 要求在开放不同权限团队前补齐此边界。

## What Changes

- 新增服务端源访问策略：主体、数据源、工具、目标、环境、目的、凭据与目的地绑定，明确拒绝优先。
- 提交快照保留策略版本，每次实际派发、结果接受和历史材料读取重新核对最新授权；最新授权不能扩大固定快照。
- 新增版本化模型出站字段规则、禁止凭据、授权会话内随机一致别名；映射仅服务端保存。
- 策略缺失、失效、无法读取、未知材料类型和不能可靠约束的查询拒绝，错误只返回固定公开信息。
- 在真实 SDK 序列化后的 HTTP 边界逐请求复核策略、目的地、认证与正文；准备文本后的策略变化、协议消息、附加参数和同源重定向不能旁路。
- 对继承历史、报告附件、片段和普通用户目录/概览重新授权，配置管理员不获得其他用户私有内容读取权。

## Capabilities

### New Capabilities
- `source-access-scope`：服务端源授权、模型出站、撤权及后续共享读者授权契约。

## Impact

纯策略模块、运行时/连接器/API、会话/附件和配置选择入口及相应测试。独立模块、API 与 SDK HTTP 捕获使用 Mac 隔离合成材料，不改既有现场配置、数据、源服务、模型或密钥。真实 MiniMax 及最终代码冻结验证由主集成另记；合成传输、纯函数通过不能等同真实源业务或用户接受。R13 Case 共享尚未实现。
