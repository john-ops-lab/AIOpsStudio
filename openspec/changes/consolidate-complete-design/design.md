# Design

## Context

已有四份设计及十三项已发布实施 Issue。最新代码基线为本次开始时的远端 main；文档整合不改变实现和验收事实。

## Goals / Non-Goals

**Goals:** 一份文档可独立读懂产品定位、当前能力、目标架构、接口与持久化边界、未完成能力、开发顺序和验收要求；相关入口一致。

**Non-Goals:** 不实现功能、不变更 API 或部署、不更新 Issue 实施状态、不制造产品版本号或新的交付日期。

## Decisions

1. 使用稳定文件名 `docs/design/EasyOps完整设计.md`，文档日期与源码基线分别记录；保留 v0.5 架构来源，不将整合文档修订号当成新产品版本。
2. 先给状态矩阵，每章分别标记现有机制与待开发契约；“代码已实现”不表示当前运行验证、根因正确率或用户接受。
3. 以主规格和当前源码解释现有行为；旧设计中未实现的身份历史、Fact/Claim、执行中自动续跑、工单和 Case 等保留为未来契约，不能直接拼接成现有事实。
4. 四份来源文档保留兼容入口和来源记录，新增完整设计作为阅读主入口。十三项工作包及依赖保持上一轮已确认版本，不因合并重新设计或闭项。
5. 核对标题、关键契约、E01–E21 验收与 R01–R13 工作包覆盖，独立检查每个重要状态声明。公开材料仅用通用示例和相对代码路径，不包含现场值和私有报告索引。

## Risks / Trade-offs

- [拼接导致状态矛盾] → 按主题合并与消重，已实现和目标逐项标记，历史验证不改写。
- [完整文档过长] → 状态矩阵和目录优先，实施工作包集中在后部，读者无需来回打开四份来源。
- [多个主入口再次漂移] → 根 README、设计索引和来源文档指向同一完整设计，来源保留为修订沿革。
- [发布泄露现场信息] → 使用现有暂存树及推送历史安全门禁，私有比对只读执行，不发布原始研究和运行材料。

## Migration Plan

无运行或数据迁移。发布整合文档及验证记录，正常提交推送后核对当前提交 CI；后续功能以独立 OpenSpec 实现变更推进。
