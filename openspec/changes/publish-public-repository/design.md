# Design

> 历史公开初始化设计的去标识化副本。当前公共 checkout、外置部署参数和 Git 历史处理由 `sanitize-public-history` 定义。

## Context

应用源码、正式设计与私有运行材料原本分开保存，需要提供可独立阅读的公共源码和文档，同时保持现有运行实例。

## Goals / Non-Goals

发布源码、正式设计、OpenSpec 与有边界的验证摘要；保留原应用运行位置和私有数据，不迁移数据库或改写用户历史。

## Decisions

1. 当时以应用仓库发布，正式设计副本放入 `docs/design/`，不把含私有运行材料的目录作为仓库根。
2. 根 LICENSE 采用 MIT；第三方依赖和 OpenSpec 工作流保留各自许可与版权说明。
3. 公开验证保留需求映射、计数、首次失败、oracle 修正及 `partial` 边界，原始会话和证据不上传。
4. 发布前检查工作树及拟推送历史中的已知凭据，推送后比较远端主分支和文件树；不在文档嵌入原提交标识。
5. 初次公开直接同步 main，不创建版本标签或 Release；后续对外操作按具体授权执行。

## Risks / Trade-offs

- 已知凭据检查不等于环境去标识化；原公开包仍需后续独立审查，当前由新变更处理。
- 历史文档不能直接当作当前安装指南，安装和外置参数以根 README 为准。
- 当前文件清理不能证明历史对象或远端缓存消失，需要单独检查远端可达性并记录限制。

## Migration Plan

首次公开准备文档与可审查提交，创建仓库并核对公开属性和文件。保持原本机应用运行，不重启、不迁移数据。后续历史重建独立跟踪，不把两次工作的结果混写。
