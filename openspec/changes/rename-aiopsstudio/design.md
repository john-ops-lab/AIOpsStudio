# Design

## Context

本次从已发布版本改名为 AIOpsStudio，是同一产品和仓库；应用已有多用户、会话、证据及独立持久数据。旧名字可出现在历史或受控兼容逻辑中，不得继续出现在当前产品展示和新安装默认配置。

## Goals / Non-Goals

**Goals:** 当前品牌、代码入口、协议两端、文档和 GitHub 一致；新安装与旧部署均可验证，用户配置/凭据/历史不丢失。

**Non-Goals:** 不删除重建仓库、不重写 Git 历史、不更换模型或外部数据源、不执行源端操作、不新增产品功能。

## Decisions

1. 品牌 AIOpsStudio，Python 包 aiopsstudio，distribution aiopsstudio-workbench，Node agent aiopsstudio，主环境前缀 AIOPSSTUDIO_。新旧环境值相同可共存，冲突明确拒绝。
2. 新 session Cookie 使用新名；旧 Cookie 只验证原有效会话并有界迁移，不创建特权或延长既有有效期，冲突拒绝，退出清除两种名称。
3. 新库使用新表前缀，存在完整旧表组时复用已有表，不复制/重命名生产数据；残缺/混合命名拒绝。新默认状态和 Docker 资产使用新名，识别已有状态时保留原数据库/卷/归属，不接管同名无关资产。
自定义状态目录仅通过新配置键指定时，要求外部数据库 URL 或完整 database.container/volume/user/name；新空目录与再次启动采用同一规则。保留旧 STATE_DIR 时（同值双键也可）保留旧资产选择；不同值拒绝，不从私有文件猜测归属。

4. 安全扫描优先读取新 profile Git 键，兼容旧键但冲突/失效拒绝；helper 只读识别新旧表组，不导入应用初始化。旧图片历史路径与批准哈希保留，新品牌图使用新路径，经目视/OCR/元数据复核后批准，不能为扫描放行改规则。
5. 同一 GitHub repository ID 原位改名，保留 MIT、Issues/讨论、分支与历史；同步新地址、工作区目录和正文链接。若插件缺改名能力，使用已有 GitHub CLI/API，不请求重复授权。
6. 先在隔离 Mac 环境验证包、环境与存储兼容、登录、AG-UI、UI与安全门禁，再处理已有本机实例。原配置/历史保持原值，保留回退，未完成运行迁移不能宣称全量完成。

## Risks / Trade-offs

- [标识替换导致空库/孤立卷] → 识别旧完整资产并复用，混合/不确定失败，不自动复制生产数据库。
- [协议或 Cookie 两端错位] → Node/Provider 同步新 agent，端到端本机登录与协议检查，旧 Cookie 按原期限迁移。
- [历史图片无法通过完整扫描] → 新图新路径，保留历史旧字节批准；不绕过门禁，不改历史。
- [泛化替换误改其他产品] → 真实竞品品牌和历史事实不误写成新项目，只改本项目当前标识；残留逐项分类。

## Migration Plan

公开副本先实施并验证。现有实例先只读清点配置、存储与活跃任务，准备同样的数据身份和可恢复的代码/入口；迁移时不重置口令、主密钥、数据库和会话历史。所有验证在 Mac，不部署 N100。最后对当前工作树、运行展示、仓库与 Issue 做全范围完成审计。
